# Modern image codecs in the Go/MyGo app

Verified on 2026-11-11 on macOS arm64 / Apple M6, Darwin 27.2.0, Go 1.27.3, Node 26.13.0, pnpm 11.20.0, MyGo 0.9.0. The implementation and packaged app are on `migration/mygo`; nothing was committed, pushed, or publicly released during this evaluation.

Follow-up on 2026-11-12: [the codec selection review](mygo-codec-selection.md) retains these pins, exempts the independent WebP implementation from the WASM mutex, and records the rebuilt package validation. The exact measurements below describe the 2026-11-11 build.

## Supported behavior

| Format | Import, thumbnail, full-resolution comparison | Encode and export |
| --- | --- | --- |
| JPEG / PNG | Yes | Yes; JPEG quality control, PNG lossless |
| WebP | Yes, content sniffing | Yes; quality control and alpha |
| AVIF | Yes, content sniffing | Yes; quality control, lossless alpha, 4:4:4 chroma |
| JPEG XL (`.jxl`) | Yes, raw codestream and container registration | Yes; quality control, quality 100 lossless |
| HEIF / HEIC | HEVC still images supported by the bundled HEIC decoder | Conversion into any output format above; no HEIF encoder |

The picker, drop validation, macOS file associations, output dropdown, default format selection, gallery upload extensions, MIME registry, and backend format validation use the expanded capabilities. HEIF imports default to AVIF output. Other encodable source formats retain their format by default. Backend inspection identifies content even with an unrecognized extension.

Previews and comparison images are decoded by Go into JPEG/PNG data URLs, so the WebView does not need native support for the original codec. Transparent thumbnails use PNG. Comparison retains full image dimensions. Export preserves the generated bytes and existing user files.

## Fixed implementations and build conditions

| Go module | Version | Selected implementation |
| --- | --- | --- |
| `github.com/gen2brain/webp` | v0.6.4 | Bundled libwebp translation, method 4, exact transparent RGB |
| `github.com/gen2brain/avif` | v0.6.0 | Bundled WASM, speed 8, alpha quality 100, 4:4:4 |
| `github.com/gen2brain/jpegxl` | v0.6.0 | Bundled libjxl WASM, effort 3; lossless at quality 100 |
| `github.com/gen2brain/heic` | v0.7.2 | Bundled WASM decoder; read only |

The package scripts use `scripts/go.mjs`, which retains existing Go build flags and adds `nodynamic`. CI sets the same tag. Installed shared codec libraries therefore do not change which implementation ships. No Rust installation, Cargo invocation, Homebrew codec installation, or standalone encoder executable is required to build or run this app. Some upstream embedded assets were built with Rust; consuming those precompiled assets does not require Rust locally.

JPEG XL's selected default WASM implementation supports lossy quality control. The module also contains an optional `wasm2go` source path whose encoder has different capabilities; it is not the path evaluated here. Tests verify that quality changes the bytes and output size, and that quality 100 preserves pixels on a transparency fixture.

`scripts/notices.mjs` collects the pinned modules' supplied LICENSE/NOTICE/COPYING texts, including their bundled library notices, into `resources/codec-notices.txt`. Packaging runs this collection and copies the result into `Pic Piper.app/Contents/Resources/codec-notices.txt` (verified, 41,129 bytes).

## Concurrency correction

A fresh-process race test exposed unsynchronized WASM runtime version initialization when JPEG XL decoding and encoding first started concurrently. The selected JPEG XL module also shares configuration between its independently initialized decoder and encoder.

`internal/imaging/codecs.go` serializes modern codec configuration, decoding, and encoding across service instances. Standard JPEG/PNG processing remains parallel. This favors predictable correctness over maximum modern-codec batch throughput. The service still bounds expensive operations to two workers.

The regression deliberately overlaps AVIF encoding, JPEG XL encoding/configuration, and HEIC decoding. It is run separately with `-race` so earlier tests cannot hide the first-use path by warming the runtime:

```bash
node scripts/go.mjs test -race ./internal/imaging -run '^TestModernCodecsConcurrentFirstUse$' -count=1
```

The initial failing race result was reproduced before the guard. This isolated test and the full race suite pass after the guard. CI includes the isolated test.

The synthetic smoke source is a 1200 × 800 patterned gradient, JPEG quality 98, 188,246 bytes. The actual packaged UI at quality 85 produced the sizes below. The checked-in benchmark recreates that source and measures one warm encode into memory, excluding first-use WASM compilation, source decoding, disk I/O, preview generation, and UI overhead.

| Output | Actual UI output bytes | One warm encode |
| --- | --- | --- |
| JPEG, quality 85 | 60,110 | 6.49 ms |
| PNG, lossless | 898,805 in benchmark | 50.82 ms |
| WebP, quality 85 | 26,472 | 110.73 ms |
| AVIF, quality 85 | 67,126 | 174.69 ms |

```bash
node scripts/go.mjs test ./internal/imaging -run '^$' -bench '^BenchmarkEncodeFormats$' -benchtime=1x -count=1
```

This is a reproducible sanity sample, not a photography quality benchmark. The same quality number does not imply equal visual quality across encoders, and one synthetic gradient cannot rank formats generally. Some outputs can be larger than the input.

## Limits

- Static-image workflow only. Animation and extra frames are not retained.
- HEIF is a container family; only images supported by the selected HEVC decoder are promised, rather than every HEIF brand/codec combination. No HEIF/HEIC output encoder is exposed.
- Re-encoding strips metadata, including GPS. JPEG XL losslessness means decoded pixels, not reversible JPEG bitstream reconstruction.
- AVIF preview and export apply container rotation/mirroring. Its initial inspection dimensions can reflect stored dimensions for a rotated container; full comparison uses decoded dimensions. Comprehensive AVIF/HEIC orientation-fixture coverage remains future work.
- HDR, wide-gamut ICC/color fidelity, and high-bit-depth roundtrip guarantees have not been established. Validate representative camera files before relying on those properties.
- Modern codec work is serialized to protect bundled runtime state. No performance claim is made for large batches or the 40-million-pixel input limit.
