# Repository Guidelines

## Stack and boundaries

Pic Piper uses Go/MyGo and React. Use the current package scripts and Go module for builds and tests.

- React features and their behavior tests live together under `src/features/`.
- `src/api/backend.ts` owns typed operation wrappers and structured business errors. `src/platform/desktop.ts` owns native dialogs, clipboard, and file-open/drop subscriptions.
- `src/mygo.ts` is generated by `pnpm generate`; change bound Go methods instead of editing generated bindings.
- Keep `main.go` focused on native window lifecycle and bridge routing. Put image behavior in `internal/imaging` and S3/settings/naming in `internal/cloud`.
- Bound Go methods run concurrently. Protect shared state and keep expensive image operations bounded.
- Use `scripts/go.mjs` for Go commands so codec selection stays independent of installed shared libraries. Keep modern codec calls behind the adapter in `internal/imaging/codecs.go`; bundled dependencies have shared initialization state.

## Verification

Before handing off implementation changes, run:

```bash
pnpm test
pnpm build:web
pnpm test:go
node scripts/go.mjs test -race ./...
node scripts/go.mjs test -race ./internal/imaging -run '^TestModernCodecsConcurrentFirstUse$' -count=1
node scripts/go.mjs vet ./...
test -z "$(gofmt -l main.go main_test.go smoke.go internal scripts/icon)"
```

For window, native integration, or packaging changes on macOS, also run `pnpm build` then `pnpm smoke`. Inspect the generated screenshots and report under `build/smoke-*`; a successful compilation does not establish GUI usability. The smoke driver uses private test data and a loopback bucket. Native OS pickers, physical Finder drops, and real provider credentials require separate validation.

Add behavior regressions for image orientation/transparency, safe output paths, S3 signing/object conflicts, credentials, and naming when changing those areas. Keep feature UI tests beside their components and Go tests beside their modules. Use `gofmt` for Go and match nearby TypeScript naming and style.

## Data and security

Use synthetic fixtures and fake credentials in tests and screenshots. Real S3 credentials, presigned URLs, and bucket tokens must not appear in logs or commits. Credentials are private local files rather than encrypted shared storage; retain restrictive permissions and atomic writes. Exports and downloads must preserve existing user files. Compression output must remain within the app-owned cache before export.

## Handoff

Use concise Conventional Commit titles when commits are requested. PRs should describe the resulting behavior, include UI screenshots for visual changes, explain credential behavior when affected, and state the checks actually run. See README.md for user setup and supported formats; consult docs/mygo-mvp-results.md when discussing measured app size or build performance.
